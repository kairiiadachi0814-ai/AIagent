# 経理財務アシスタント 機能一覧

最終更新: 2026-08-17（本番ルーム移行前）

Chatworkの許可ルームで「経理財務アシスタント」宛にメンションすると応答する社内AI。
さくらのVPSで24時間動いている。

参照するのは、経理財務部のマニュアル**69件**と、外部の索引6種。

| 索引 | 収録 | 用途 |
|---|---|---|
| 税法リンク集（国税庁） | 94件 | 税額・税率・課税の要否 |
| 会計基礎知識リンク集（freee） | 272件 | 簿記・会計処理の考え方 |
| 補助金リンク集（ミラサポplus） | 24件 | 補助金・助成金・支援制度 |
| マニュアルリンク集（ライズ経理財務） | 123件 | 社内マニュアルの原本URL |
| マニュアルリンク集（楽天軒） | 63件 | 同上 |
| ひな形リンク集（Box） | 37件 | 契約書・送付状などのひな形 |

---

## 1. 聞く — 質問に答える

### 社内の手順・ルール

**こう頼む**　「銀行明細ってどうやって取るんでしたっけ？」

**返るもの**　手順の要点を本文に直接。末尾に【出典】として原本の文書名と、開けるURL。

**気をつけること**　マニュアルに書いていないことは推測で埋めず「記載がありません」と返る。
どのマニュアルに追記すべきかの提案が付くことがある。

### 会計・税務の一般知識

**こう頼む**　「圧縮記帳ってなんですか？」「収入印紙、契約書にいくら貼るの？」

**返るもの**　国税庁またはfreeeのページをその場で取得して要約。税額・税率の質問は国税庁を優先する。
末尾に「当社での具体的な取り扱い・税務判断は税理士にご確認ください」。

### 補助金・支援制度

**こう頼む**　「省力化投資補助金って今どうなってる？」

**返るもの**　ミラサポplusのページを取得して要約。公募中かどうかも添える。
末尾に「実際の要件・金額・期間は公式サイト・公募要領でご確認ください」。

**気をつけること**　金額・要件・公募期間は変わるため、記憶では答えない。索引に無ければ正直に「記載なし」と返す。

### 法令・条文

**こう頼む**　「下請法の支払期日って何日以内でしたっけ？」

**返るもの**　e-Gov法令検索で条文の原文を取ってから回答。法令名・条番号・e-GovのURL入り。
末尾に「法的判断や契約書の内容確認は、顧問弁護士への相談またはLegalForceでのリーガルチェックを経てください」。

**気をつけること**　記憶で条番号を断定しない。条文を取れなければ正直にそう返す。

### 出典の付き方（共通）

- 社内手順の回答には必ず【出典】が付く。表示名は**原本の文書名**（内部のファイル名は出さない）
- 本文のURLはマニュアルの記載と一字一句照合し、一致しないものは「（URL省略）」に置き換わる
- 出典が1件も確認できない回答は返さず、正直に「確かな根拠を見つけられませんでした」と返す

## 2. 渡す — 文書を読ませる

### 議事録・要約

**こう頼む**　ファイルを添付したメッセージの中でメンションして「この文字起こしから議事録作って」

**返るもの**　■決定事項／■宿題（担当・期限）／■次回予定 の形にまとめた本文。
「どの文書に基づいたか」を必ず明記する。

**気をつけること**　添付を忘れて後から送った場合も、「議事録」「要約」などの語があれば直前の添付を遡って探す。
会話としての受け答え（「添付ありがとうございます」）から始めてから成果物を出す。

### 契約書の要点・印紙税

**こう頼む**　契約書PDFを添付して「要点まとめて。印紙はいくら必要？」

**返るもの**　契約の種類／当事者／期間・自動更新／金額・支払条件／解約条件／管轄・秘密保持・再委託 の要点。
印紙税は号数の判断根拠と、国税庁の一覧表から取った税額。

**気をつけること**　条項が有利か不利か、法的に問題ないかは**判断しない**（LegalForce・顧問弁護士の領域）。
気になる点は「リーガルチェックで確認を」と伝えるにとどまる。

### 対応する形式と上限

| 対象 | 上限 |
|---|---|
| 1ファイルあたり | 20MB |
| PDF | 合計15MB・合計50ページ |
| 読み取るテキスト | 12万文字（超えた分は打ち切り、その旨を回答冒頭に明記） |
| 一度の添付 | 5ファイルまで（超過分は案内） |

**対応**　PDF（スキャン画像も可）／.docx／.txt／.md／.csv／.tsv／.log／GoogleドキュメントとスプレッドシートのURL

**非対応**　旧形式の.doc／画像／音声 — 正直にその旨を伝え、PDFか.docxでの保存し直しを案内する

## 3. 作らせる — 書類を作る

### 書類送付状

**こう頼む**　「エムズステップ南様宛に送付状作って。送付物は倉庫寄託契約書1通」

**返るもの**　Wordの下書きをChatworkに添付。本文に使ったひな形名とBox URL。

**ひな形**　ライズクリエイション／ヤマトライジング／楽天軒（RAKUTENKEN）の3種

### FAX送付状

**こう頼む**　「三十三銀行の奈良支店あてにFAX送付状。件名は海外送金添付資料の件、送信枚数3枚」

**返るもの**　Excelの下書きを添付。宛先が台帳（15件）にあれば、FAX番号・TEL・担当者まで自動で入る。

### 共通の決まり

- 依頼文に無い宛先・書類名・部数は**推測で埋めない**。足りなければ作らずに聞き返す
- 差出人の担当者は、Chatworkで依頼した人の苗字が入る（依頼文で指定すればそちらが優先）
- 部数の指定が無いものは1部と仮置きし、その旨を返信に書く
- 出来上がりは常に**下書き**。印刷・送付・提出は人が行う
- 契約書は作らない。「業務委託契約書を作って」はひな形のURL案内＋LegalForceチェックの案内になる
- Chatworkへの添付は1ファイル5MBまで（送付状・FAX送付状はいずれも20KB程度）

## 4. 頼む — 雑務・報告

### 文面の下書き・計算・整形

**こう頼む**　「取引先に送る督促メールの下書き作って」「この3社の請求額を合計して」

**気をつけること**　依頼文にある材料だけで作る。分からない金額・日付・名前は勝手に決めず「◯◯」のまま残す。
社内ルールを使う作業（締め日変更の周知文など）はマニュアルに忠実に作り、出典を付ける。

### マニュアルを更新したときの報告

**こう頼む**　「銀行明細取得のマニュアル、手順を更新しました」

**返るもの**　対象マニュアル名を復唱した受領返信。反映待ちリストに記録され、管理者へ通知が飛ぶ。

**気をつけること**　報告しただけでは**中身は反映されない**。反映は管理者の作業（原本→転記→デプロイ）。
反映が済むまでは少し前の内容で答えることがある。

### 回答への指摘

**こう頼む**　「さっきの締め日の回答、実際は25日締めですよ」

**返るもの**　お詫びと受領の一言。改善リストに記録され、管理者へ通知が飛ぶ。反論や弁明はしない。

**気をつけること**　自分でコードを直すことはしない。修正は管理者が確認して行う。

## 5. 勝手に動く — 自動実行

### 議論ウォッチャー（5分ごと・いまは見習いモード）

ルーム内のメンバー同士のやり取りを巡回し、**出典で裏取りできた明らかな誤りだけ**に横から助言する。

- 2段階で判定する。1段目は軽く「誤りの疑い」だけを拾い、疑いがあるときだけ2段目でマニュアル・法令に照らして裏取りする
- 意見の相違・雑談・予定調整・判断が分かれる話題には**口を挟まない**。迷ったら黙る
- 1日3回まで。同じ根拠での再介入は同日中はしない
- **見習いモード（shadow）で稼働中** — ルームには投稿せず、管理者ルームへ内報だけ。精度を確認してから公開モードへ切り替える（設定変更のみ）
- ボット宛のメンションとボット自身の発言は対象外。発言の恒久保存はしない

### 週次自己分析（毎週月曜9時）

先週分の記録を集計してレポートを作る。答えられなかった質問、リンク切れになった参考URL、反映待ちの更新報告、未対応の指摘。

### 費用の上限管理

月**15,000円**が上限。70%（10,500円）に達すると管理者へ通知。
上限に達するとエージェントは停止し、その旨をルームに返す。

## できないこと・気をつけること

| できないこと | 補足 |
|---|---|
| 契約条項の妥当性判断 | 有利／不利、法的に問題ないかは判断しない。LegalForceと顧問弁護士の領域 |
| 契約書の作成 | ひな形のURL案内に留まる |
| マニュアルの自動更新 | 更新報告は記録するだけ。反映は管理者作業 |
| 自分のコードの修正 | 指摘は改善リストへ。修正は管理者が確認して行う |
| 社外への送付・提出 | 作るのは下書きまで。送るのは人 |
| 旧形式.doc／画像／音声の読み取り | PDFか.docxへの保存し直しを案内する |
| 許可リスト外のルームでの応答 | 無応答（設定で管理） |

**注意点**

- 話し方の決まり（免責文を付ける、法的判断をしない、パスワードを転記しない等）は、
  多くがAIへの指示として担保している。コードで機械的に止めているのは、出典の実在チェック、
  URLの照合、ルーム制限、費用上限、Markdownやタグの除去。
- 同時に依頼が集中すると、**合計10件**まで受け付け、11件目からは「混み合っています」と返る。
  この場合Chatworkが再送しても再処理されないため、時間をおいて頼み直す必要がある。
- マニュアルを直した場合、サーバー上のファイルなら最大5分で反映される。
  原本（Googleドキュメント等）を直しただけでは自動追従しない。

## 管理者向け：本番ルームへ移すときに変える設定

`config/config.json`

| キー | 現在（テスト） | 本番で |
|---|---|---|
| `allowed_room_ids` | `[444781726]` | 本番ルームIDを追加。テストルームを残すかは運用次第 |
| `admin_room_id` | `444781726` | 管理者専用ルームへ分けると、内報が本番ルームに流れない |
| `discussion_watch.room_ids` | `[444781726]` | 巡回対象の本番ルームID |
| `discussion_watch.mode` | `shadow` | 実績を見てから `live` へ。当面は `shadow` のまま |
| `monthly_cost_limit_jpy` | `15000` | 利用者が増えるため実績を見て調整 |

**あわせて確認**

- Chatwork側で、本番ルームにエージェントアカウントを参加させる
- Webhookの対象ルームに本番ルームを追加する
- 本番ルームでウォッチャーが初めて動くとき、その時点までの発言は「既読」にするだけで評価しない
- 反映待ちリスト（`pending_updates.jsonl`）と改善リスト（`feedback.jsonl`）は追記専用。
  対応済みの消し込みは手作業（放置すると週次レポートに毎週載り続ける）

**運用の入口**

- 死活監視: `GET /healthz`
- ローカル確認: `python run_local.py "<質問>"`（Chatworkを介さず回答と当月累計額を確認）
- 監査ログ: `/var/log/raizuinu/audit-YYYYMM.jsonl`（90日保存）
- 状態ファイル: `/var/lib/raizuinu/`
- 定期実行: `raizuinu-watcher.timer`（5分ごと）／`raizuinu-selfreview.timer`（月曜9時）
